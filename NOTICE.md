Graphics, display-server and audio-device libraries are deliberately **not**
bundled - they must bind to the host's drivers. sndio is bundled despite
being an audio library because it is a client of the `sndiod` daemon rather
than of a device: with no daemon running, OpenAL falls through to its ALSA
or PulseAudio backend, both of which still resolve against the host. ALSA
itself stays unbundled, so `libasound.so.2` remains a host requirement.

## OpenAL Soft source code

OpenAL Soft is licensed under the GNU Library General Public License
version 2. Both packages carry it unmodified, as a separate shared library
the executable loads at run time; a user may replace it with a compatible
build of their own. On Windows `OpenAL32.dll` sits beside `openpete.exe`
and is replaced in place. In the AppImage it is `usr/lib/libopenal.so.1`
inside the image: `--appimage-extract` unpacks the image to
`squashfs-root/`, where the file is replaced and `squashfs-root/AppRun`
starts the game with `usr/lib` first on the loader path. Its complete
corresponding source is offered from the download host `dl.openpete.com`,
the same place as the packages, at the URLs below. SHA-256 follows each file.

## In the repository, not in any distributed build

Present under `third_party/` or produced there by a setup script. No release
archive carries them, so they have no table row and no text under
`licences/`.

- cubeb (`third_party/cubeb`, submodule) - ISC (`third_party/cubeb/LICENSE`).
  https://github.com/mozilla/cubeb. No CMake target builds it.
- DuckStation (`third_party/duckstation`, submodule pinning upstream
  `e4c55ad0283f`) - CC BY-NC-ND 4.0 (`third_party/duckstation/LICENSE`).
  https://github.com/stenzek/duckstation. The reference emulator the
  gameplay oracle captures its golden trace from; never linked, never
  packaged. openpete's own additions to it are the series
  `third_party/duckstation-patches/` (files of its own, MIT like the rest
  of openpete, and the lines it inserts, located by hashes of upstream
  text; it carries no upstream text, and an inserted line is part of an
  upstream DuckStation file once applied), which `scripts/setup_duckstation.sh` applies to the pinned
  upstream on the developer's machine; no modified DuckStation is
  distributed.
- FFmpeg 6.1.1 and x264 (`third_party/ffmpeg-mingw/`, gitignored) - GPL:
  `scripts/setup_mingw_ffmpeg.sh` configures FFmpeg with `--enable-gpl
  --enable-libx264`. https://ffmpeg.org, https://code.videolan.org/videolan/x264.
  Linked statically into a `windows-mingw` executable for `--record` only
  when the prefix exists, which makes that executable GPL; a dist preset
  refuses the combination at configure (`core/CMakeLists.txt`), and
  `scripts/dist_compliance.py scan` refuses an archive whose binaries carry
  an FFmpeg or x264 marker. A native Linux build outside the dist presets
  links the host's FFmpeg libraries (`libavformat`, `libavcodec`,
  `libavutil`, `libswscale`, `libswresample`) dynamically for `--record`;
  both dist presets set `OPENPETE_ENABLE_RECORD` off.
- PSXRecomp's runner FMV decoder
  (`third_party/psxrecomp/runner/src/fmv_player.cpp`): its header states its
  MDEC decode and IDCT are ported from FFmpeg's `libavcodec/mdec.c` and
  `libavcodec/simple_idct_template.c` and its VLC tables are copied from
  `libavcodec/mpeg12data.c`; FFmpeg licenses those files LGPL-2.1-or-later.
  No openpete CMake file compiles the runner, so no build contains it.
- `third_party/SDL/test/`, `third_party/imgui/examples/` (with its GLFW
  copy) and `third_party/glslang/External/`: not compiled; their licence
  files are listed with scope `none` in `packaging/licences/manifest.tsv`.
- `third_party/duckstation-patches/`: openpete's patch series against the
  pinned DuckStation (see DuckStation above).

- toml11 3.7.1 and ELFIO 3.11 (`third_party/psxrecomp/recompiler/lib/toml11`,
  `.../ELFIO`) - MIT (`LICENSE`, `LICENSE.txt`).
  https://github.com/ToruNiina/toml11, https://github.com/serge1/ELFIO. On
  PSXRecomp's include path; no PSXRecomp source includes either header.
- PSXRecomp's runner build (`third_party/psxrecomp/runner/CMakeLists.txt`)
  fetches GLFW 3.3.8 and fmt 10.1.1 and compiles the vendored glad under
  `runner/lib/glad`. No openpete CMake file configures that project.

The MinGW OpenAL Soft prebuilt in `third_party/OpenAL-mingw/` (version in
`VERSION`, licence in `COPYING`) is the Win64 import library, headers and
`soft_oal.dll` (renamed `OpenAL32.dll`) of upstream's
`openal-soft-1.25.1-bin.zip`, byte-identical to it; its source is named
under OpenAL Soft source code.
