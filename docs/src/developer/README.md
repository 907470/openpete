# Developer

Reference pages for the port. [`architecture.md`](architecture.md) is the
entry point.

## Start here

- [`architecture.md`](architecture.md) - how the port is put together:
  build-time recompilation, PsyCross, the native Vulkan renderer, shared
  `g_ram`, and the per-game boundary.
- [`reference/index.md`](reference/index.md) - every function of `core/`
  and `games/` with its doxygen comment, by file and by name. Generated by
  `tools/gen_code_docs.py` (CMake target `code_docs`); not committed.
- [`building.md`](building.md) - prerequisites, the recompiler generation
  steps a fresh clone must run before configuring, the CMake preset and knob
  scheme, and dev versus distribution builds.
- [`unattended-runs.md`](unattended-runs.md) - driving the binary without a
  keyboard: headless flags, the gate scripts, and their exit codes.
- [`recording-video.md`](recording-video.md) - `--record` video capture in
  builds with libav: VFR and CFR modes, encoders, audio.

## Level data

The level notes are in the Spyro section.

- [`level-format.md`](../spyro/level-format.md) - on-disc WAD layout, the
  length-prefixed component container, and the decoded interiors of
  environment sectors, faces, textures, collision, and moby instances.
- [`level-overlays.md`](../spyro/level-overlays.md) - per-level code overlays: the
  shared `0x8007AA38` window, the id word, the `SetOverlayPointers` callback
  slots, and how the 37 same-address overlays are recompiled into
  co-resident C.

## Modding

- [Modding](../modding/index.md) - the mod-author section of this site
  (guides plus a reference generated from the API header, the symbol
  manifests and the mod gallery by `tools/gen_mod_docs.py`). The CMake
  target `docs` builds the published sections (User, Modding) into
  `build/<preset>/games/spyro-1/docs-site/`, which every package ships as
  `docs/`; `scripts/build-docs.sh`
  builds every section, and `scripts/build-docs.sh --serve` runs a live
  preview.
- [`mod-api-audit.md`](mod-api-audit.md) - caller census of every mod-API
  entry, regenerated by `tools/mod_api_census.py`.

## Renderer

- [`render-channel-census.md`](render-channel-census.md) - every feeder that
  emits triangles into the native scene: its scene categories, provenance tag
  layout, identity at emit time, and whether a material can reshade it.

## Recompiler and system boundaries

- [`psycross/`](psycross/README.md) - the fork the PsyCross submodule tracks
  and one record per change on it (symptom, root cause, fix, verification).
- [`psycross-boundary.md`](psycross-boundary.md) - the PsyCross (PSYQ
  re-implementation) ABI boundary: `u_long` and pointer-width divergence,
  which APIs are stride-safe, the 12-byte host prim header versus the PSX
  4-byte tag, and the Pass 5b guard.
- [`disc-io.md`](disc-io.md) - the disc reader every host read path uses,
  the disc cache behind it, the per-game boot-order profile, the
  `OPENPETE_DISC_TRACE` row format, and the disc checks.

## Determinism, oracle and debugging

- [`duckstation-oracle.md`](duckstation-oracle.md) - the PSX oracle end to
  end: the DuckStation fork and capture mechanism, `check_psx_oracle.sh`
  exit codes and knobs, and the CD-load transient carve-out.
- [`gte.md`](gte.md) - the GTE (`core/psx/gte.c`): what it implements and
  how, what the recompiler's inline register moves own, the instruments,
  the per-record hash row, the verification record and the residual
  classes.
- [`gte-trace-vs-reference.md`](gte-trace-vs-reference.md) - cross-checking
  openpete's GTE against PsyCross's: the in-tree two-engine CSV trace, and
  the live pcsx-redux replay for input-side divergence.
- [`ram-diff-vs-pcsxr.md`](ram-diff-vs-pcsxr.md) - single-shot 2 MiB RAM and
  CPU diff against pcsx-redux at one PC: byte-level attribution the
  DuckStation oracle cannot give.
- [`bug-reports.md`](bug-reports.md) - the bug-report zip: its members,
  `tools/bugreport.py`, `--bug-report-replay` and its exit codes, the
  replay routes, the release archive, and the harness variables.

## Porting

- [`adding-a-game.md`](adding-a-game.md) - how a PSX title becomes a game
